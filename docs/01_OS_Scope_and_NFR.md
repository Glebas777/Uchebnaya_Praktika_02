# my_os — Учебная операционная система

## 1. Название и концепция

**Название:** my_os — учебная операционная система.

**Концепция:** учебная ОС с монолитным ядром, реализованная на Python 3.10+, использующая SQLite в качестве файловой системы, журнала системных вызовов, реестра процессов и хранилища пользователей. ОС предоставляет командную оболочку, через которую пользователь взаимодействует с ядром посредством системных вызовов.

**Основная идея:** продемонстрировать принципы работы ядра ОС, разделения пространства ядра и пространства пользователя, механизма системных вызовов и разграничения прав доступа — без углубления в реальную работу с аппаратным обеспечением.

## 2. Границы операционной системы

### 2.1. Что входит в границы ОС

| Подсистема | Что реализуется |
|------------|-----------------|
| Управление процессами | Создание, запуск, завершение процессов; учёт состояний |
| Управление памятью | Выделение и освобождение памяти процессам; учёт лимитов |
| Файловая система | Хранение файлов и каталогов в SQLite; CRUD-операции |
| Разграничение прав | Аутентификация по логину/паролю (хэш SHA-256) |
| Командная оболочка | Обработка команд пользователя, вызов системных вызовов |
| Журналирование | Запись всех системных вызовов в таблицу syscalls_log |

### 2.2. Что не входит в границы ОС

| Функция | Обоснование исключения |
|---------|-----------------------|
| Реальная работа с аппаратным обеспечением | Требует знания аппаратной части; заменяется заглушками |
| Поддержка прерываний и драйверов | Слишком сложно для учебного проекта в сжатые сроки |
| Интеграция с внешними службами каталогов | Не входит в тему проекта |
| Поддержка сетевых протоколов | Не требуется для демонстрации принципов ОС |
| Графический интерфейс | Не является темой проекта |

## 3. Сценарии использования

### 3.1. Роли пользователей

| Роль | Права |
|------|-------|
| Обычный пользователь | Работа с файлами только в своём каталоге |
| Администратор | Полные права: управление пользователями и настройками |
| Система | Фоновые процессы: планировщик, сборщик мусора |

### 3.2. Основные сценарии

| № | Сценарий | Системные вызовы | Модули |
|---|----------|------------------|--------|
| 1 | Вход в систему | sys_login | shell, kernel, db |
| 2 | Создание файла | sys_create | shell, kernel, fs, db |
| 3 | Чтение файла | sys_open, sys_read | shell, kernel, fs, db |
| 4 | Запись в файл | sys_open, sys_write | shell, kernel, fs, db |
| 5 | Запуск процесса | sys_exec | shell, kernel, proc, mem |
| 6 | Просмотр процессов | sys_ps | shell, kernel, proc |
| 7 | Завершение процесса | sys_kill | shell, kernel, proc |
| 8 | Просмотр журнала | sys_log | shell, kernel, db |
| 9 | Выделение памяти | sys_malloc | kernel, mem, db |
| 10 | Завершение ОС | sys_shutdown | shell, kernel |

### 3.3. Детальный сценарий: создание файла

1. Пользователь вводит в оболочке команду создания файла.
2. Оболочка вызывает системный вызов `sys_create`.
3. Ядро проверяет права пользователя.
4. Ядро обращается к модулю файловой системы.
5. Модуль формирует запись в таблице `files`.
6. Ядро фиксирует операцию в `syscalls_log`.
7. Оболочка выводит сообщение об успехе.

## 4. Нефункциональные требования

### 4.1. Производительность

| Требование | Метрика | Способ проверки |
|-----------|---------|-----------------|
| Время обработки системного вызова | ≤ 50 мс | time.perf_counter() |
| Одновременных процессов | ≥ 10 | Запуск 10 процессов |
| Время отклика оболочки | ≤ 100 мс | Ручное измерение |

### 4.2. Надёжность

| Требование | Описание |
|-----------|----------|
| Обработка исключений | Ядро перехватывает ошибки, не падает |
| Остановка процесса при ошибке | Процесс останавливается, запись в журнал |
| Лимит памяти | Отказ в выделении, запись в журнал |

### 4.3. Безопасность

| Требование | Описание |
|-----------|----------|
| Хранение паролей | Только в виде хэша SHA-256 |
| Разграничение прав | Обычный пользователь не меняет файлы администратора |
| Журналирование | Все системные вызовы фиксируются |

### 4.4. Поддерживаемость

| Требование | Описание |
|-----------|----------|
| Модульность | Код разбит на модули, ≤ 300 строк каждый |
| Документирование | Каждый модуль снабжён docstring |
| Версионирование | Git, осмысленные коммиты |

### 4.5. Ресурсоёмкость

| Требование | Описание |
|-----------|----------|
| Python | Версия 3.10+ |
| СУБД | SQLite (встроена в Python) |
| ОЗУ | Стандартные 4 ГБ |

| № | Риск | Стратегия минимизации |
|---|------|----------------------|
| 1 | Нехватка времени | Приоритизация: ядро → БД → fs → shell |
| 2 | Блокировки SQLite | Единственное подключение |
